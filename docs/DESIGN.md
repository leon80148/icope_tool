# 設計文件

## 目標與範圍

讓診所與社區單位不必登入國健署網站就能查「長者今年能不能做 ICOPE」，並把異常項目的轉介資源與衛教單張整合成一張可列印的轉介衛教單。必須容易部署：解壓即用、不需要伺服器、帳密與資源都在介面上設定。

不做：批次查詢、病歷號反查（HIS 整合）、網頁版。

## 架構

```
IcopeTool.exe（PySide6 桌面程式，單一程序）
├─ ui/          主視窗：左側導覽（篩檢查詢｜轉介衛教單｜設定）＋對話框
├─ services/    與 UI 無關、pytest 直接測
│  ├─ hpdcs/    國健署登入與查詢（requests.Session + ddddocr 驗證碼）
│  ├─ card/     健保卡（pyscard，共用模式、不重置卡片）
│  ├─ pdf/      轉介單（fpdf2）＋單張合併（pypdf）
│  ├─ importer  Excel 社區資源盤點表 → Resource
│  └─ pack      設定包 zip 匯出／匯入
├─ store        JSON（settings / resources / materials）＋單張 PDF
└─ 資料
   ├─ 資料存放位置（可共用）：settings.json、resources.json、materials.json、materials/*.pdf、auth/
   └─ %LOCALAPPDATA%\IcopeTool（每台電腦）：config.json、logs/audit.log、logs/error.log
```

耗時工作（國健署查詢、讀卡、產生 PDF、Excel 解析、批次加入 PDF、複製資料夾）一律在背景執行緒，結果回主執行緒更新畫面（`ui/workers.py`、`ui/progress.py`）。

## 關鍵取捨

| 決策 | 理由 | 代價 |
|---|---|---|
| 桌面程式，不做網頁 | 不需要 port、防火牆、憑證與瀏覽器讀卡元件；Chrome 的 Local Network Access 會擋區網頁面呼叫本機讀卡服務 | 放棄「一台伺服器多人開瀏覽器」，改以共用資料夾支援多機 |
| PySide6 | 單一工具鏈（Python + PyInstaller）、原生表格與檔案對話框、內建 PDF 預覽與列印 | 畫面全部重寫 |
| JSON 檔＋共用資料夾，不用資料庫 | 寫入只發生在管理操作；人看得懂、備份就是複製資料夾、NAS 零設定 | 不做跨機鎖，同一筆資料以最後寫入為準（有衝突提示） |
| fpdf2 排版 | 不需 Qt 即可測試、字型內附輸出一致 | 版面用程式畫 |
| PyInstaller onedir | Qt 與 onnxruntime 用 onefile 每次啟動要解壓數百 MB；onedir 秒開且符合 LGPL 動態連結 | 發佈的是資料夾（zip） |
| 驗證碼辨識打包進去 | ddddocr 對 hpdcs 驗證碼命中率高；載入失敗就改人工輸入 | 打包體積約 300 MB |
| 8 個評估項目固定 | 國健署表單固定；資源與單張以項目標籤掛上去 | 新增項目要改程式 |
| 客製化＝院所先設定、日常明確帶入 | 「簡單上手」與「客製化」靠分工兼顧：院所把固定會給的資源與單張設為院所預設，日常人員只勾項目、按一次帶入、核對後列印（13 次點擊降到 6 次） | 多一次「帶入」點擊（不做勾選即自動加入：誤勾會把沒人選過的內容印出去） |
| 客製化不做成範本／版型／外掛系統 | 只開放院所真的會改的資料：資源、單張、院所預設、各項衛教重點；標題、前言與版面固定 | 想改版面要改程式 |

## 資料模型（`models.py`）

- `Settings`：`clinic`（名稱、電話、地址、頁尾附註）、`hpdcs`（正式／試辦計畫、自訂計畫代碼）、`sheet.domain_notes`（院所寫的各項衛教重點：固定八項、每項 200 字與 6 行以內、預設空白）。
- `Resource`：名稱、類型、適用項目、常用、院所預設、聯絡人、電話（多支）、服務時間、地址、網站、備註、啟用。名稱＋地址用來去重。
- `Material`：名稱、說明、建議項目、檔名、排序、頁數、大小、sha256、啟用、院所預設。sha256 用來去重。
- `LocalConfig`（每台電腦）：資料存放位置、讀卡機、最近的評估人員、是否隱藏設定清單。
- 三個概念分開：`domains`＝出現在哪些項目的建議清單、`pinned`（常用）＝排在最上面、`include_by_default`（院所預設）＝按「帶入院所預設」時加入。舊檔案沒有的欄位一律以預設值載入。

## 院所預設與轉介單草稿（`ui/referral/state.py`）

- 預設只在使用者按「帶入院所預設」時加入，而且一次只處理「已勾選、還沒帶入過、院所有設預設」的項目；按鈕上方寫出這次會處理哪些項目，帶入後回報實際新增的數量。沒有預設的項目不會被標成已帶入。
- 資源逐項加入（不走勾選資源時的跨項目套用），已處理過的項目不會因為帶入另一個項目而被補回。
- 單張記錄「由哪些項目帶入」：取消勾選項目時，只由它帶入的單張一起離開；使用者自己勾選、取消或按「勾選所有建議的單張」的單張，從此不再跟著項目走。重新勾回項目只還原暫存的資源，預設要再明確按一次才會帶入。
- 兩個追蹤欄位只描述目前勾選的項目（`default_materials` 的 key ⊆ `defaults_applied` ⊆ `domains`），所以換長者「保留勾選」不必另外處理，`has_selections()`／`is_empty()` 也不需要知道它們。
- 畫面上的資源與單張清單一起換新、或都留著上一份：不拿「新資源＋舊單張」這種混合版本來帶入預設。

## 只印衛教單張（`ui/dialogs/leaflet_print.py`）

- 獨立對話框、自己的勾選，不讀寫轉介單草稿與它的 PDF 版本／完成狀態；不加首頁、不含姓名，沒有國健署帳號與診所名稱也能用。
- 每次輸出綁定不可變的工作快照（資料夾、單張 id／檔名／登錄雜湊、清單順序）與請求編號。合併在背景做，合併進去的就是驗過雜湊的那份內容；「重試列印」「用 PDF 閱讀器開啟」會先在背景重讀來源比對內容（檔案長度與修改時間相同不算證據），通過才輸出同一份合併檔。
- 忙碌狀態涵蓋「背景工作 → 檢查 → 系統列印視窗」整段；背景工作結束不會解除它，所以列印視窗開著時的資料更新與重複點擊不會重入，回到閒置再補做清單更新。
- 關閉（取消、Esc、X）讓請求作廢；還有背景工作沒回來時對話框先不銷毀，等回呼清掉自己的暫存檔。交給外部閱讀器的檔案留給一天清理機制。

## 各項衛教重點

- 院所衛教文字儲存在共用資料夾，可供同院電腦使用；資源與單張設定包不包含這些文字，合併與取代兩種匯入都不會動到它。
- 正規化（統一換行、去首尾空白、不截字）只有一個函式，模型載入、編輯器計數、變更與衝突比對、儲存、PDF 都用它；手改檔案造成的超限文字會保留，儲存與「包含該項目的轉介單」才會被擋下。
- PDF：文字印在項目標題下、資源之前，沒有資源時也印。標題＋衛教重點＋第一筆資源放得進一頁就排在一起（續頁要扣掉續頁頁首），放不進去就正常續頁；比一頁高的資源區塊也不再整塊推到下一頁（會讓前一頁大片空白）。

## 共用資料夾的寫入規則

- 只提供單筆操作（新增、更新、刪除某個 id）：每次先重讀檔案、套用這一筆、寫到暫存檔再 `os.replace`；Windows 短暫鎖檔時重試。UI 從不整批覆寫清單，避免 A 機蓋掉 B 機剛新增的資料。
- 每 15 秒比對三個 JSON 的修改時間，其他電腦改過就通知各頁重新載入；正在編輯中的設定不會被默默覆蓋，改為顯示衝突提示，儲存前再比對一次。
- 資料夾無法存取（NAS 離線）時，開啟程式會請使用者重新選擇或結束，不會自動改回本機（避免產生兩份資料）。

## 國健署查詢（`services/hpdcs`）

- 登入：`POST /Login.ashx`（帳號、密碼、5 碼驗證碼）→ `GET /Default.aspx`。驗證碼先自動辨識，只在回應訊息含「驗證碼」時重試；其他登入失敗一律停用自動登入，直到重新儲存帳密（避免帳號被鎖）。
- 查詢：`/EardlyFunction_V2/{計畫}/EF2_CheckIDExist.aspx`，解析結果為 已登錄／已在其他計畫登錄／可評估／無法評估。計畫代碼依民國年自動推導（`EFA_115`、`EFA_Pilot_115`）。
- 登入 cookie 存在共用資料夾，多台電腦共用同一個登入狀態；逾時時先改用其他電腦較新的 cookie，仍失效才重新登入。
- 同一天同一人的結果暫存；查詢可以取消（每個請求前與等待鎖時檢查）。
- 協定細節與實際回應範本見 `docs/hpdcs_protocol.md` 與 `tests/fixtures/hpdcs/`。

## 個資與安全

- 查詢紀錄只在記憶體，關閉程式即清除。健保卡的出生日期也一樣：只用來在查詢結果旁核對年度年齡（65 歲，原住民 55 歲），跟著讀卡當下的身分證走，不寫進稽核或任何檔案；年齡只是提醒，判定仍以國健署為準。
- 稽核紀錄只記事件與身分證 sha256 前 8 碼；密碼不出現在畫面、紀錄、錯誤訊息或設定包。
- 產生的轉介單 PDF（含長者姓名）與單張合併檔寫在本機暫存資料夾，超過一天自動清除，不放在共用資料夾。
- 帳密以明文存在資料存放位置的 `auth/`；安全邊界是該資料夾的 Windows 存取權限（見安裝說明）。

## 介面原則

- 評分依 Nielsen 10 大可用性原則與 WCAG 2.2 AA（`docs/ui-review/RUBRIC.md`），每輪由 Claude、Codex、advisor 獨立評分後交叉討論（`docs/ui-review/SCORES.md`）。
- 資料正確性優先：查詢結果綁定當次查詢的快照；轉介單綁定長者身分，換人先確認；PDF 以內容版本判斷是否過期，不會印出舊內容。
- 色彩：一般文字 ≥ 4.5:1、輸入框邊線 ≥ 3:1；鍵盤焦點統一用近黑色外框，與選取狀態的顏色分開。
- 樣式集中在全域 QSS，以動態屬性切換狀態（`ui/theme.py`），不在個別元件 `setStyleSheet`，大量清單勾選才不會卡。
- 內容可能超過螢幕高度的區塊改為捲動，主要動作（列印）固定在可見位置。
