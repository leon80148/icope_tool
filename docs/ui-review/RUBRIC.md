# UI/UX 評分標準

本專案的 UI/UX 評分採用業界最常用的專家評估法：**Nielsen Norman Group 的 10 大可用性原則（Heuristic Evaluation）**，
問題嚴重度採 **Nielsen 嚴重度量表（0–4）**，並加上 **WCAG 2.2 AA** 的無障礙基本門檻。

## 使用情境（評分時請以此為準）

| 項目 | 內容 |
|---|---|
| 使用者 | 診所櫃檯人員、護理師、個管師；電腦熟悉度不一，部分年紀較長 |
| 環境 | Windows 10/11 桌機，螢幕 1366×768 到 1920×1080；門診時段忙碌、長者在旁等候 |
| T1 篩檢查詢 | 插健保卡或輸入身分證 → 知道「今年能不能做 ICOPE」，目標 20 秒內 |
| T2 轉介衛教單 | 勾選異常項目 → 選轉介資源與衛教素材 → 印出給長者，目標 2 分鐘內 |
| T3 初次設定 | 診所資訊、國健署帳號、匯入資源 Excel、加入衛教 PDF，目標 15 分鐘內 |
| 印出的轉介單 | 讀者是長者與家屬，需大字、清楚、知道要找誰 |

## 評分方式：10 項原則 × 各 10 分 = 100 分

| # | 原則 | 評什麼 |
|---|---|---|
| H1 | 系統狀態可見性 | 查詢中、登入中、讀卡中、產生 PDF 中、儲存成功與否是否即時清楚 |
| H2 | 系統與真實世界吻合 | 用語是否為臨床與櫃檯日常用語；流程順序是否符合門診實務 |
| H3 | 使用者控制與自由 | 能否取消（讀卡、查詢）、回上一步、清除重來、復原變更；誤按有沒有退路 |
| H4 | 一致性與標準 | 按鈕層級、顏色語意、文字、版面、Windows 慣例（Enter、Esc、Ctrl+P、Delete） |
| H5 | 錯誤預防 | 身分證檢查碼、必填檢核、刪除確認、取代匯入的二次確認、帳號鎖定保護 |
| H6 | 辨識而非回憶 | 選項直接可見、建議資源與素材標示、查詢紀錄、姓名自動帶入 |
| H7 | 彈性與使用效率 | 快捷鍵、讀卡一鍵查詢、搜尋、批次操作、記住評估人員、效能與反應速度 |
| H8 | 美學與極簡設計 | 視覺層級、資訊密度、留白、對齊、只顯示當下需要的資訊 |
| H9 | 協助辨識、診斷與復原錯誤 | 錯誤訊息是否說明原因與下一步，並提供可點的復原動作 |
| H10 | 說明與文件 | 內建說明、欄位提示、空狀態引導、首次使用引導 |

每項給分錨點：

| 分數 | 意義 |
|---|---|
| 10 | 典範，找不到問題 |
| 8–9 | 只有外觀層級的小瑕疵（嚴重度 1） |
| 6–7 | 有小的可用性問題（嚴重度 2） |
| 4–5 | 有主要可用性問題（嚴重度 3） |
| 0–3 | 有災難性問題（嚴重度 4） |

## 問題嚴重度（Nielsen 0–4）

| 等級 | 意義 |
|---|---|
| 0 | 不是可用性問題 |
| 1 | 外觀問題，有空再修 |
| 2 | 小問題，優先度低 |
| 3 | 主要問題，必須修，優先度高 |
| 4 | 災難，上線前一定要修 |

## 封頂規則（避免總分灌水）

- 仍有未解決的**嚴重度 4** 問題 → 總分最高 70。
- 仍有未解決的**嚴重度 3** 問題 → 總分最高 89。
- **WCAG 2.2 AA 基本門檻**，任一項不符算嚴重度 3：
  一般文字對比 ≥ 4.5:1（大字 ≥ 3:1）、主要流程可全程用鍵盤操作、鍵盤焦點清楚可見、
  只有圖示的按鈕要有可讀名稱、錯誤不能只靠顏色表達。

## 流程

1. `python tools/ui_snapshots.py docs/ui-review/round-NN` 產生各畫面與狀態的截圖（1366×768 為主，另有 1920×1080 與列印 PDF）。
2. 三方獨立評分：Claude、Codex（gpt-6-astra）、advisor。
3. 交叉討論：彼此檢視對方的問題清單，確認或反駁，合併成一份問題清單。
4. 依嚴重度修正後進入下一輪。
5. **該輪分數 = 討論後的共識分數；仍有歧見時取最低分。** 達 95 分且無嚴重度 3 以上問題才結束。
6. 每輪結果記錄在 `SCORES.md`。
