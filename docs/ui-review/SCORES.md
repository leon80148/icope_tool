## Round 05 — 產品設計討論（不是缺陷評分，不產生新分數）

第 01–04 輪是依 `RUBRIC.md` 找缺陷、評分；這一輪不同：維護者提出產品方向，由 Claude 與 Codex（gpt-6-astra，同一個討論串連續五輪）討論後凍結範圍，再實作。以下是設計與驗收的共識紀錄，不代表取得新的介面分數，也不是現場驗證。

- 日期：2026-09-17；基準版本 `a42ea9b`；討論原文：`round-05/r1–r5_prompt.md`、`r1–r5_reply.md`；截圖：`round-05/1280x720/`。
- 維護者的要求：介面容易上手、不要太複雜；每個主要功能可以模組化或客製化（例如轉介資源、衛教單張）；讓護理師或診所人員很容易就把衛教單印出來。

### 五輪各自決定了什麼

| 輪次 | 重點 | 結論 |
|---|---|---|
| 1 | 日常路徑實算與張力 | 三項異常的共同情境是 13 次點擊（不是原估的 15–20 次）；真正的負擔是「每位長者都要重新判斷院所通常給什麼」。以分工化解「簡單 vs 客製」：院所先設定、日常人員明確帶入並核對。Codex 反對「勾項目就自動加入」。 |
| 2 | 互相反駁 | Claude 接受明確帶入（誤勾不會把沒人選過的內容印出去），但要求逐項、可再次帶入；Codex 接受並補上「帶入不得走跨項目套用」「已帶入與內容完整度分開」。單張列印由「草稿內的輸出模式」改為獨立對話框；主要按鈕不隨資源數量切換強調。 |
| 3 | 範圍凍結 | 八項納入、不做清單定案；Codex 修正 8 個規格點（摘要文案不得謊報已帶入、重勾後是否待帶入要重新判斷、`prune` 不清已帶入標記、單張對話框的快照與清理等）。 |
| 4 | 具體設計審查 | Codex 列出 12 個「粗心實作會交付的缺陷」（`SheetPrefs` 被容錯清空、新增 PDF 時旗標沒傳、`on_finished` 太早解除忙碌、重試繞過來源驗證、最後編輯的衛教項目漏存、只靠文字抽取驗證分頁等），全部轉成測試。 |
| 5 | 驗收條件與風險 | Codex 否決以檔案大小＋修改時間代替內容驗證（同長度覆寫再還原 mtime 可重現），改為背景比對內容雜湊；對話框自行延後銷毀須證明不殘留、不永久等待；驗收證據要到列印邊界並核對文件內容。 |

### 凍結的範圍

| # | 項目 | 做法 |
|---|---|---|
| 1 | 逐項明確帶入院所預設 | `Resource`／`Material` 加 `include_by_default`；摘要卡固定區顯示「本次帶入：…」與按鈕；草稿追蹤 `defaults_applied`、`default_materials`；旗標隨設定包攜帶 |
| 2 | 固定的確認捷徑 | 第一、二步：主要「下一步」＋最右側次要「確認與列印」，只導覽、不送印 |
| 3 | 只印衛教單張 | 頁首與第二步空狀態開啟同一個獨立對話框；無首頁、不碰轉介草稿；快照、請求作廢、來源內容驗證 |
| 4 | 帶入範圍與輸出摘要 | 待帶入／已帶入過／沒有預設三種狀態如實顯示，回報實際新增數量 |
| 5 | 依任務說明首次設定 | 「依需要完成設定」，各項寫明用途，不再有「完成 X/4」 |
| 6 | 保留六個設定分頁 | 「診所資訊」改為「診所與轉介單」，頁內捲動、復原／儲存固定在下方 |
| 7 | 用語統一 | 現行介面與文件的「衛教素材」改為「衛教單張」；識別子、JSON、歷史紀錄不改 |
